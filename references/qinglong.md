# 青龙面板部署标准

## 复用统一入口

让青龙、GitHub Actions和本地运行同一业务入口，不复制签到逻辑。默认 Python 3 命令为：

    PYTHONPATH=src python3 -m checkin.main

若项目已安装为包，可使用：

    python3 -m checkin.main

提供可直接执行的入口脚本或模块，并确保从仓库根目录运行。不得依赖 GitHub Actions 专属上下文、路径或变量。

## 安装依赖

在部署文档中给出从仓库根目录执行的命令：

    python3 -m pip install -r requirements.txt

若使用 `pyproject.toml` 管理包，再给出与其一致的安装方式。固定或约束依赖版本，说明升级步骤。不要假设青龙预装 requests、httpx、通知库或浏览器运行时。

浏览器自动化只有在站点分析证明必要且不涉及安全挑战时才安装；默认生成纯 HTTP 客户端。

## 创建定时任务

给出明确的仓库目录和命令占位符，例如：

    cd /path/to/generated-checkin && PYTHONPATH=src python3 -m checkin.main

推荐使用避开整点的五字段 cron，例如：

    17 7 * * *

要求用户按青龙版本和任务界面确认 cron 字段数及容器时区。把 IANA 时区同时传给应用，用于日期判定和日志显示；不得仅凭宿主机显示猜测时区。只在用户要求时增加小范围可配置抖动。

若站点分析证实存在二维码、设备授权或 OAuth 等正常交互登录，另建一个**仅手动运行**的登录任务，例如 `python3 login.py --store qinglong`。该任务不得配置 cron。它等待用户本人完成官方登录后读取成功响应中的白名单 Cookie，并通过已验证的青龙 OpenAPI 新增或更新环境变量；API 鉴权从受保护变量读取，Cookie 不得出现在日志、命令参数或失败回退文本中。确切命令、变量名、青龙版本/API 依据和账号更新规则写入站点专用 `docs/cookie-setup.md` 与 `DEPLOY_QINGLONG.md`。

## 配置环境变量

在青龙“环境变量”界面创建配置，不把秘密写入任务命令、脚本参数或仓库文件。

至少说明以下类别：

- 单账号认证变量；
- 多账号结构化 JSON 变量；
- IANA 时区；
- 连接与读取超时；
- 安全重试上限；
- 可选通知配置；
- 日志级别。

在生成项目中列出最终采用的确切名称。优先沿用 `CHECKIN_COOKIE`、`CHECKIN_TOKEN`、`CHECKIN_ACCOUNTS`、`CHECKIN_TIMEZONE`、`CHECKIN_CONNECT_TIMEOUT`、`CHECKIN_READ_TIMEOUT`、`CHECKIN_MAX_RETRIES` 和 `CHECKIN_NOTIFY_CONFIG`；删除不适用于目标站点的变量，不同时要求互斥的认证变量。

使用纯占位符给出多账号示例：

    [
      {"name":"account-1","cookie":"<REDACTED_COOKIE>"},
      {"name":"account-2","token":"<REDACTED_TOKEN>"}
    ]

让应用校验 JSON、字段类型、认证方式和重复别名。错误日志只显示账号索引或非敏感别名，不回显整段变量。

## 保护日志与文件

- 在应用日志边界统一脱敏；
- 禁止打印青龙环境变量、完整请求头、原始响应和异常请求对象；
- 禁止把秘密写入仓库、缓存、临时调试文件或任务命令；
- 确认任务日志只包含账号别名、阶段、状态和脱敏摘要；
- 调试结束后删除临时响应、截图和 HAR；
- 让每个账号使用独立会话，避免 Cookie 串用。

按 [安全规范](security.md) 处理凭据轮换和泄露。

## 配置通知

把通知作为可选适配器：

- 默认只输出脱敏日志；
- 仅在用户选择渠道后声明相应环境变量；
- 不假设面板已安装某个第三方通知库；
- 优先使用项目内的轻量 HTTP 适配器或明确依赖；
- 只发送账号别名、状态和安全业务摘要；
- 明确通知失败是否影响最终退出码，不得掩盖核心签到失败。

若用户使用青龙自带通知能力，先确认当前面板提供的接口，再接入；不得臆造路径、模块名或变量名。

## 支持多账号运行

- 默认串行或低并发执行；
- 为每个账号独立捕获异常并继续后续账号；
- 对非幂等签到请求先查状态再重试；
- 最终输出各状态计数；
- 只在所有账号均为 `SUCCESS` 或 `ALREADY_DONE` 时返回 0；
- 让任务退出码与本地和 GitHub Actions 保持一致。

## 编写部署与排障步骤

在 `DEPLOY_QINGLONG.md` 中说明：

1. 如何拉取或上传项目；
2. 如何确认 Python 3 版本；
3. 如何安装和更新依赖；
4. 如何创建单账号或多账号环境变量；
5. 如何创建 cron 任务并设置时区；
6. 如何手动执行统一入口；
7. 如何查看脱敏日志和退出码；
8. 如何配置或关闭通知；
9. 如何更新 Cookie、Token 和刷新凭据；
10. 若存在交互登录，如何手动运行登录任务并确认环境变量已安全新增或更新；
11. 如何禁用任务。

按状态排障：

- `CONFIG_ERROR`：检查变量是否存在、JSON 是否有效；
- `AUTH_EXPIRED`：通过正常登录流程更新凭据；
- `TEMPORARY_ERROR`：检查网络、限流、`Retry-After` 和服务状态；
- `SITE_CHANGED`：重新收集脱敏 Network 或响应样例；
- `UNSUPPORTED_SECURITY_CHALLENGE`：停止自动化，不尝试绕过。
- `ACCESS_DENIED`：停止任务并核对账号权限或站点政策，不重试、不绕过。

## 交付前验证

- 在不提供秘密时运行入口，确认友好报错且不泄露配置；
- 使用 mock 配置验证单账号与多账号；
- 检查 cron 命令可从指定目录启动；
- 检查项目不引用 `GITHUB_*`、`RUNNER_*` 等 GitHub 专属变量；
- 检查通知库不是隐式前置条件；
- 检查非零失败退出码能被青龙任务记录。
