# 测试与验证规范

## 分层测试

建立以下测试层级：

1. **单元测试**：验证配置、状态映射、重试决策、脱敏、通知摘要和退出码；
2. **模拟集成测试**：用 mock HTTP transport 验证完整“查状态—签到—验结果”时序；
3. **项目结构验证**：检查文档、部署文件、入口、Secrets 接口和安全约束；
4. **可选 live test**：仅在明确授权和显式开关下调用真实站点。

默认执行前三层。不得把“模块能导入”或“进程能启动”当作完成。

## 使用可复现的 mock 与 fixture

- 拦截所有 HTTP 请求，不依赖公网；
- 为请求方法、脱敏 URL、头部白名单、参数类型和调用顺序写断言；
- 使用虚构域名、虚构账号和不可用占位符；
- 删除真实 Cookie、Token、个人数据和生产响应；
- 保存最小响应字段，不复制无关页面或完整生产数据；
- 固定时间、时区、随机种子和退避时钟，避免睡眠和不稳定测试；
- 把 fixture 按“成功、已签到、认证过期、限流、结构变化”等语义命名；
- 让 CI 在意外真实网络访问时立即失败。

## 覆盖必需场景

至少创建以下测试：

| 场景 | 关键断言 |
| --- | --- |
| 配置读取与字段校验 | 缺失、空值、类型错误返回 `CONFIG_ERROR`，不回显原值 |
| 单账号解析 | 构造一个独立账号配置 |
| 多账号解析 | 保持顺序、隔离凭据、拒绝无效 JSON 和重复别名 |
| 成功响应 | 同时验证业务字段或签到后状态，返回 `SUCCESS` |
| 已签到响应 | 不重复提交，返回 `ALREADY_DONE` 并视为成功 |
| Cookie/Token 过期 | 返回 `AUTH_EXPIRED`，不无限刷新 |
| CSRF 缺失或失效 | 重新获取一次正常 CSRF 或返回有证据的失败状态 |
| 网络超时 | 只按安全策略重试，最终返回 `TEMPORARY_ERROR` |
| 429 限流 | 尊重 `Retry-After` 和最大重试次数 |
| 5xx 临时错误 | 使用指数退避；非幂等请求不得盲重试 |
| 响应结构变化 | 不误判成功，返回 `SITE_CHANGED` |
| 日志秘密遮盖 | 日志、异常和通知均不出现原始秘密 |
| 部分账号成功、部分失败 | 所有账号均执行，汇总计数正确，退出非零 |
| 重试防重复签到 | 超时后先查状态，已完成时不再 POST |

若项目生成站点专用交互登录，再用完全 mock 的接口覆盖二维码/设备码生成、等待确认、过期、拒绝、成功、取消和总超时；断言仅从成功响应接收白名单 `Set-Cookie`，并验证青龙 OpenAPI 或 GitHub CLI 存储适配器通过内存/标准输入传值、不进入参数和日志。默认 CI 不调用真实登录接口或生成可用二维码。

再覆盖 403、409、HTML 登录页伪装成 200、重定向到其他域名、通知失败和未知异常，确保状态映射有证据。

## 验证 HTTP 行为

对每个关键请求断言：

- 连接和读取超时已设置；
- User-Agent 明确且诚实；
- 必需头存在，完整秘密不进入断言失败输出；
- 认证头不会跟随到未授权域名；
- GET 等安全请求的重试次数和退避正确；
- 签到 POST 只有在已确认幂等时直接重试；
- `Retry-After` 的秒数或日期格式被安全处理；
- 达到上限后停止，不形成刷新或重试死循环。

用虚拟时钟验证退避，不让测试真实等待。

## 验证状态、汇总与退出码

- 为七个标准状态分别创建断言；
- 验证 `SUCCESS` 和 `ALREADY_DONE` 返回退出码 0；
- 验证其他状态映射到实现契约定义的非零退出码；
- 构造混合状态，验证固定优先级和各状态计数；
- 验证某个账号抛异常不会阻止后续账号；
- 验证日志和通知只使用非敏感账号别名。

## 验证脱敏

在同一个测试中把唯一秘密值放入：

- 请求头、Cookie 和 URL 查询参数；
- JSON、Form 和多账号配置；
- 响应片段、异常消息和对象 `repr`；
- 重试日志、通知内容和最终摘要。

捕获所有输出并断言秘密值完全不存在，同时断言字段名和 `[REDACTED]` 仍可用于排障。增加大小写变体、Unicode、短值和嵌套容器测试。

## 隔离 live test

只有同时满足以下条件才执行真实接口测试：

- 用户的直接请求已涵盖目标账号和该项正常操作；
- 用户主动设置 `LIVE_TEST=1`；
- 凭据仅来自受保护环境变量；
- 测试不是 Pull Request、fork 或默认 CI 自动路径；
- 使用专用低权限账号并遵守站点频率；
- 测试不会绕过安全挑战或扩大操作范围。

把 live test 标记为默认跳过。运行前输出目标域名、操作类型和脱敏账号别名供确认；不得输出凭据。运行后不保存真实响应、HAR、截图、Cookie 或 Token。遇到安全挑战立即停止并返回 `UNSUPPORTED_SECURITY_CHALLENGE`。

## 执行交付门禁

至少运行项目声明的完整离线测试命令和生成项目验证器。例如，标准库模板运行：

    python tests/run_offline.py
    python scripts/validate_generated_project.py <generated-project>

若项目选择 pytest，则改用 `python -m pytest -q`，并在依赖清单中明确固定或约束 pytest 版本。

若用户提供的是现有 Node.js 项目，使用其锁文件对应的 `npm ci`、`npm test`/项目实际测试命令和 lint；继续强制断网 mock、秘密扫描、POST 防重复与部署检查。仓库内 `validate_generated_project.py` 只验收 Python 生成项目，不得把它的通过结果用于证明 Node.js 项目正确。

根据项目实际工具补充 YAML 解析和静态检查。然后确认：

- 默认测试全程离线；
- 所有必需场景通过；
- GitHub Actions YAML 可解析；
- 青龙命令能够启动统一入口；
- 缺失秘密时友好失败且退出非零；
- fixture、日志和测试报告不含真实站点信息或秘密；
- `docs/cookie-setup.md` 已从该站点证据生成，包含精确获取模式、输出处理和 Secret 目标，不是通用 F12 教程；
- 测试后未留下会话文件、`.env`、响应缓存或调试 artifact。
