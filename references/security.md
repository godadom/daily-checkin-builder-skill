# 授权、安全与秘密管理

## 强制执行授权边界

只处理用户本人账号或用户已取得明确授权的账号，并只复现正常客户端可见、站点允许的签到行为。允许分析浏览器可见请求、CSRF Token 和客户端公开执行的必要签名流程，但不得借此规避安全控制。

遇到授权不明、范围扩大或材料疑似来自他人账号时立即停止。不得协助：

- 窃取、导出或复用他人的 Cookie、Token、密码、会话或浏览器数据库；
- 暴力破解、撞库、批量注册、刷奖励或滥用活动规则；
- 绕过 CAPTCHA、WAF、Turnstile、reCAPTCHA、hCaptcha、设备证明、WebAuthn、短信验证或反机器人挑战；
- 绕过付费、权限、地区、速率或访问控制；
- 隐藏自动化身份、进行隐蔽爬取、攻击或规避检测；
- 伪造设备、账号归属或授权证明。

若正常流程要求安全挑战，按 [CamoFox 与 noVNC 人工接管](camofox-human-handoff.md) 让用户本人在可视会话中手动完成。CamoFox 只用于经授权的正常浏览、诊断和人工接管；它的可用性不授权使用反检测、代理轮换、指纹伪装、挑战求解或重放能力。无法完成人工接管，或无人值守任务仍依赖挑战时，返回 `UNSUPPORTED_SECURITY_CHALLENGE`。

## 约束秘密生命周期

让秘密只通过运行时环境变量、GitHub Secrets 或青龙环境变量进入进程。禁止把秘密写入：

- 源码、注释、模板、测试 fixture；
- README、部署文档、分析文档或 `SECURITY.md`；
- 工作流 YAML、cron 命令或命令行参数；
- 日志、异常、通知、缓存、artifact 或测试快照；
- `.env.example`、版本控制历史和生成报告。

让 `.env.example` 只保留变量名和不可用占位符。对多账号使用结构化环境变量并校验格式，不把原始值写入错误信息。

使用最低权限、最短可行生命周期的凭据。站点提供正式刷新机制时只实现该机制，不模拟或绕过登录挑战。

## 在所有输出边界脱敏

统一实现一个可测试的脱敏器，并在日志、异常、HTTP 调试、通知和运行摘要输出前调用。至少识别：

- `Cookie`、`Set-Cookie`；
- `Authorization`、Bearer Token；
- `Token`、Refresh Token、Access Token；
- `Password`、Secret、API Key；
- 用户配置声明为敏感的字段；
- URL 查询参数和请求体中的同类字段；
- 手机号、邮箱、设备标识等用户明确标记的个人数据。

执行以下规则：

- 按字段名大小写不敏感匹配，并支持嵌套字典、列表和对象；
- 保留字段名，统一用 `[REDACTED]` 替换完整值；
- 对字符串化异常、URL、cURL 和调试文本再做模式脱敏；
- 禁止打印完整请求头，即使已知其中只有部分敏感字段；
- 禁止记录原始响应正文；只提取经过白名单允许的业务字段；
- 防止秘密通过对象 `repr`、堆栈局部变量、重试日志或通知回调泄露；
- 对短值、Unicode、大小写变体和多账号 JSON 编写回归测试。

不要依赖 GitHub 的自动掩码或青龙界面隐藏作为唯一保护。

## 安全处理用户材料

- 在读取 HAR、cURL、截图或已有代码前检查是否脱敏；
- 把 cURL 当作数据解析，不直接执行；
- 不运行来源不明的脚本、浏览器扩展或二进制文件；
- 不把用户提供的 URL、分支名、账号别名或参数直接拼接进 shell；
- 不把材料上传到未获授权的第三方服务；
- 只把最小必要的脱敏摘要写入 `docs/site-analysis.md`；
- 测试结束后不持久化运行时秘密、真实响应或会话缓存。

## 限制网络与重试风险

- 仅在用户明确授权时调用真实站点；
- 默认让测试使用 mock，不访问真实网络；
- 对可能产生副作用的 POST 仅在确认幂等时直接重试；
- 未确认幂等时先查询状态，再决定是否重试；
- 尊重限流和 `Retry-After`，使用低频、低并发；
- 不把随机延迟或代理轮换用于规避反机器人系统；
- 遇到异常重定向到其他域名时停止发送认证头并重新审查。

## 审查依赖与工作流

- 优先选择标准库、维护活跃的明确依赖和官方 Action；
- 固定版本；高安全场景对 Action 固定经核验的完整提交 SHA；
- 不编造 SHA，不安装来源不明的通知包；
- 不授予工作流不需要的写权限；
- 不缓存秘密或包含秘密的调试文件；
- 在差异审查中重点检查新增 URL、日志、环境变量、shell 命令和网络依赖。

## 处理凭据泄露

一旦发现真实秘密进入对话、文件、日志或提交：

1. 停止继续使用该凭据；
2. 通知用户立即在原服务撤销或轮换；
3. 清理工作区、日志、artifact 和缓存中的副本；
4. 若已提交到 Git，说明仅删除最新文件不等于清除历史，要求按仓库策略清理历史；
5. 用新凭据更新受保护的 Secret 或环境变量；
6. 复查访问日志和异常活动；
7. 增加覆盖该泄露路径的脱敏测试。

不得在报告中重复泄露值。

## 生成项目的 SECURITY.md

要求生成的 `SECURITY.md` 至少说明：

- 不要提交或分享真实凭据；
- 如何撤销和轮换泄露凭据；
- 如何用占位符提交脱敏问题报告；
- 报告中可包含的状态码、字段名和脱敏时序；
- 项目不会绕过哪些验证码、WAF、设备证明、WebAuthn、短信验证和访问控制；
- 如何私下联系维护者；若没有安全联系渠道，就明确不要在公开 Issue 粘贴凭据。

交付前执行秘密扫描、日志脱敏测试和人工差异审查。
