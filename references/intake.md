# 输入确认与材料脱敏

## 用户请求即为范围声明

用户直接要求分析、生成或修复其签到自动化时，记录为其对以下事项的声明：账号由其本人持有或已获授权、仅复现正常客户端可见行为、用途不包含刷奖励或滥用活动，以及其请求中明确写出的站点与取证范围。直接开始分析，不要求用户回复固定的授权句式，也不因同一范围的正常取证反复索取确认。

仅在账号归属或范围不清、目标是绕过安全控制、材料疑似来自他人账号，或新操作超出原请求范围时暂停并澄清；不要索取更多凭据。真实网络调用仅限该直接请求已涵盖的正常取证范围，默认测试仍使用 mock，且不得扩展到其他站点、账号或副作用操作。

## 使用输入问卷

按顺序收集以下信息。先复述已知答案，再只询问仍会影响实现的项目：

1. **站点**：站点名称、入口 URL、签到页面 URL。
2. **范围**：站点、账号归属与自动化许可已由直接请求声明；仅在不明确或冲突时补问允许的测试范围。
3. **目标**：新建项目、修复现有项目，或只分析流程。
4. **部署**：本地、GitHub Actions、青龙，或同时支持多种环境。
5. **运行时**：新建项目使用 Python 3；只有用户已提供 Node.js 签到项目时才沿用 Node.js，并记录其包管理器、锁文件和原生测试命令。
6. **计划**：本地签到时间、IANA 时区、是否需要小范围随机延迟。
7. **账号**：单账号或多账号；多账号是否允许低并发。
8. **认证**：Cookie、Bearer Token、API Key、OAuth、Token 刷新或其他机制；Cookie 优先按 [Cookie 获取与会话续用](cookie-acquisition.md) 使用正常响应的 `Set-Cookie` 或已证实的正式流程，无法程序化获得时再给出人工导出说明。
9. **材料**：接口文档、脱敏 cURL、脱敏 HAR、Network 截图、前端代码、已有脚本、成功与失败响应。
10. **通知**：仅日志，或 Telegram、PushPlus、Server酱、企业微信等明确渠道。

不得要求用户在对话中粘贴真实秘密。若必须验证字段形状，要求保留字段名并用占位符替换字段值。

## 在接收前要求脱敏

要求用户保留请求结构、字段名、状态码和必要的类型信息，同时替换以下值：

| 数据 | 使用的占位符示例 |
| --- | --- |
| Cookie / Set-Cookie | `<REDACTED_COOKIE>` |
| Authorization / Bearer Token | `Bearer <REDACTED_TOKEN>` |
| API Key / client secret | `<REDACTED_API_KEY>` |
| 密码 / 刷新令牌 | `<REDACTED_SECRET>` |
| 手机号 / 邮箱 / 姓名 | `<REDACTED_PII>` |
| 用户 ID / 设备 ID / 指纹 | `<REDACTED_IDENTIFIER>` |
| 地址、订单、余额明细等个人数据 | `<REDACTED_PERSONAL_DATA>` |

脱敏时执行以下规则：

- 保留 Cookie 名称，替换每个 Cookie 的值；
- 保留 Token 的类型、前缀和大致用途，不保留任何可复用片段；
- 检查 URL 查询参数、请求体、响应体、重定向地址和截图，不只检查请求头；
- 从 HAR 中删除或替换 `cookies`、`headers`、`queryString`、`postData` 和响应内容里的秘密与个人数据；
- 对签名样例保留算法、字段顺序、编码方式和虚构输入，替换密钥、随机数、设备标识和真实摘要；
- 对已有代码检查源码、注释、测试、历史样例、`.env`、调试输出和缓存文件；
- 不接收浏览器配置文件、Cookie 数据库、密码库、私钥或未经裁剪的用户数据目录。

把用户提交的 cURL 当作待解析文本。不得直接执行未知 cURL，也不得把其中的值复制到命令行、生成文件或日志。

## 处理缺失信息

把缺失项分为三类：

### 必须阻塞

在以下情况继续前先取得明确答案：

- 用户请求未能说明目标站点或其账号/自动化范围，且无法安全推断；
- 不知道目标站点或签到入口；
- 请求涉及验证码、WAF、设备证明、WebAuthn、短信验证或访问控制；
- 请求的真实调用超出其直接请求已声明的正常取证范围；
- 关键材料仍包含可复用凭据或他人个人数据。

### 可以先分析

在以下信息缺失时继续整理证据，但明确标为“未确认”：

- 具体签到时间或通知渠道；
- 单账号还是多账号；
- 尚未提供成功、已签到或认证过期样例；
- 尚未确认某个动态字段的来源；
- 尚未选择 GitHub Actions 或青龙。

不得因缺少样例而编造 URL、字段、状态码、CSRF 来源、Token 刷新方式或成功条件。

### 使用安全默认值

只有默认值不改变站点行为时才采用：

- 使用 Python 3；
- 先生成本地可测试入口，不启用真实网络测试；
- 先采用单账号串行执行，并保留可扩展的账号模型；
- 默认仅输出脱敏日志，不启用第三方通知；
- 默认不随机延迟；用户需要时再增加小范围抖动；
- 未确定时区时不生成自称准确的定时换算，要求补充 IANA 时区。

## 输出确认记录

在进入站点分析前输出一份简短确认记录，包含：

- 已确认的授权与范围；
- 目标平台和运行时；
- 已收到且已脱敏的材料清单；
- 仍缺失的信息；
- 采用的安全默认值；
- 禁止执行的动作；
- 是否允许真实网络调用。

用户补充材料后更新这份记录，避免依赖先前猜测继续实现。
