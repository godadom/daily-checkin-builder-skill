# 账号密码、验证码与人机验证交互登录

本流程运行在生成脚本的部署环境中，用于手动建立或更新 Cookie。它不是签到 cron 的一部分，也不用于自动求解人机验证。根据目标站点的真实 DOM、Network 和登录状态生成站点专用适配器；证据不足时停止，不猜选择器、接口、验证码字段或成功条件。

## 选择登录方式

- `password_login`：打开正式登录页。默认让用户在可视浏览器中直接输入账号密码；只有用户明确选择自动填充时，才从受保护环境变量读取账号密码并填入已验证的同源表单，绝不从对话、命令参数或配置文件读取。
- `otp_login`：打开正式短信或邮箱验证码登录页。用户在可视页面输入手机号/邮箱、请求验证码并手动填写；若站点证据支持，程序可点击已验证的“发送验证码”按钮，但不得读取短信、邮箱或剪贴板，不得自动填充一次性验证码。
- `interactive_login`：二维码、设备授权或 OAuth 等站点正式交互流程。用户本人确认后，程序只接收正式成功结果。

三种模式都允许登录前或点击登录后出现 Turnstile、reCAPTCHA、hCaptcha、WAF、滑块或其他人机验证。程序只识别“需要用户操作”状态并保持同一浏览器上下文，不点击、拖动、识别、求解或提取挑战产物。

## 使用同一可视浏览器会话

站点适配器必须使用 Playwright 等普通可视浏览器能力，并从登录开始到 Cookie 保存结束保持同一 context/page：

1. 打开已验证的 HTTPS 登录 URL，并限制导航到站点分析列出的允许 origin；
2. 本地桌面以 headed 模式启动，用户可以直接输入账号、密码或验证码；
3. 自动填充模式只从受保护环境变量读取值，填入固定选择器后立即删除局部引用，不输出字段值；
4. 点击已验证的登录/发送验证码按钮后，同时观察登录成功、明确失败、OTP 等待、人机验证和页面结构变化；
5. 出现人机验证时切换为 `WAITING_FOR_CHALLENGE`，保持窗口可操作并提示用户完成；不重新加载、换 context、清 Cookie 或重复提交；
6. 用户在原页面完成后继续观察，只有命中已验证成功 URL、DOM 或响应判据才进入 `SUCCESS`；
7. 从当前 context 的允许 origin 读取 Cookie，只保留 `docs/cookie-setup.md` 列出的名称，拒绝缺失项、意外域、控制字符和超长值；
8. 保存后关闭 context，删除临时 profile、截图、HAR、下载和缓存。

不要把登录页返回的原始错误、DOM、请求头或异常对象直接写日志。状态提示使用固定文本与非敏感账号别名。

## 本地调出登录窗口

在有桌面的电脑上，生成的 `login.py` 提供明确命令，例如：

    python login.py --account account-a --ui headed --store local

`--account` 只接受非敏感别名；账号、密码和验证码不是命令参数。默认由用户在弹出的站点页面输入。如果选择环境变量自动填充，站点专用文档必须列出确切变量名并说明它们只在本次手动登录进程中读取。

窗口必须从登录开始就可见。这样无论人机验证在输入前、输入后还是提交后出现，用户都能在原页面完成，程序无需把挑战复制到另一会话。

## 为青龙生成本地配套登录助手

青龙没有交互桌面，生成项目不得在青龙中创建浏览器登录任务，也不得要求安装可视浏览器运行时。站点专用 `login.py` 始终由操作者在自己的 Windows、macOS 或 Linux 桌面运行，例如：

    python login.py --account account-a --ui headed --store qinglong

执行以下边界：

- 本地助手打开普通 headed 浏览器；账号密码、短信/邮箱验证码和人机验证都由用户在站点原页面输入或完成；
- 浏览器从登录开始到 Cookie 提取结束保持同一 context，不把挑战或登录表单搬到青龙；
- `--store qinglong` 使用本地受保护环境变量中的青龙基址、Client ID 与 Client Secret，并只连接用户配置的 HTTPS 青龙实例；
- 登录成功后只把站点分析白名单内的 Cookie 写入确切的青龙环境变量；账号密码和一次性验证码永不发送到青龙；
- 青龙 OpenAPI 的路径、版本、查询、新增与更新语义必须有当前实例或正式文档证据，不得猜测；
- API 写入失败时返回 `STORAGE_ERROR`，不打印 Cookie。若本地无法访问青龙 OpenAPI，则生成站点专用的面板人工录入步骤，明确目标变量名与字符串处理规则；
- 青龙 cron 只执行统一签到入口。登录助手不能加入青龙任务、GitHub Actions 或任何定时计划；
- 本地缺少图形桌面、可用浏览器或已验证站点适配器时返回 `LOGIN_UI_UNAVAILABLE`，不得降级为隐藏浏览器或远程公开登录界面。

生成的 `DEPLOY_QINGLONG.md` 必须给出本地助手安装与运行命令、本地青龙 OpenAPI 变量名、连接检查、账号别名到青龙环境变量的更新规则、总超时和人工面板回退步骤；同时明确青龙只安装签到运行时依赖。

## 状态机

可视登录至少使用以下固定状态：

| 状态 | 含义 |
| --- | --- |
| `WAITING_FOR_CREDENTIALS` | 等待用户输入账号密码，或等待受保护值填入 |
| `WAITING_FOR_OTP` | 验证码已请求或页面要求验证码，等待用户输入 |
| `WAITING_FOR_CHALLENGE` | 页面要求人机验证，等待用户在同一窗口完成 |
| `SUCCESS` | 已验证登录成功且白名单 Cookie 已保存 |
| `REJECTED` | 站点明确拒绝账号、密码、验证码或用户取消 |
| `TIMEOUT` | 超过站点专用总等待时间 |
| `SITE_CHANGED` | 登录 DOM、URL、响应或 Cookie 契约变化 |
| `STORAGE_ERROR` | 登录成功但受保护环境变量保存失败 |
| `LOGIN_UI_UNAVAILABLE` | 操作者电脑无法启动本地 headed 可视会话 |

`WAITING_FOR_CHALLENGE` 是手动登录过程中的可恢复状态；无人值守签到任务自身遇到挑战仍返回 `UNSUPPORTED_SECURITY_CHALLENGE`，不得尝试唤起长期远程浏览器。

## 保存 Cookie

- 青龙：只在确认版本与 OpenAPI 后新增/更新站点专用环境变量；API Client ID/Secret 来自受保护变量。失败时返回 `STORAGE_ERROR`，不得打印 Cookie 供复制。
- GitHub：登录助手在用户本机运行，通过已登录 GitHub CLI 的标准输入调用 `gh secret set`；不得在 Actions 中显示登录 UI 或保存浏览器 artifact。
- 本地：进程不能修改父 shell。使用用户明确选择的系统秘密存储、权限受限且被忽略的加载文件，或在同一进程中立即运行一次签到；不要声称永久设置了父进程环境变量。

多账号逐个手动登录，每个账号使用独立临时 context 和非敏感别名；不得复用 profile 或把 Cookie 合并到其他账号。

## 离线测试

对生成的站点适配器使用 mock 页面/浏览器协议，至少覆盖：

- 手动账号密码输入与受保护值自动填充；
- OTP 请求、等待、过期、错误和重新请求上限；
- 人机验证在输入前、输入后和提交后出现，且状态机保持同一 context；
- 用户完成挑战后成功、用户取消和总超时；
- 登录失败、页面结构变化、跨 origin 导航和缺失 Cookie；
- Cookie 白名单、账号隔离、青龙新增/更新与 GitHub CLI 标准输入；
- 所有日志、异常和测试失败都不含账号、密码、验证码、Cookie 或页面原文；
- CI 不启动真实浏览器登录、不访问真实站点、不调用真实青龙 OpenAPI。
