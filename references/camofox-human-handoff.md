# CamoFox 与 noVNC 人工接管

仅在用户明确授权分析本人或其有权管理的账号，并且页面出现 Cloudflare Turnstile、reCAPTCHA、hCaptcha、WAF 页面、设备证明、WebAuthn、短信验证或类似安全挑战时使用本流程。目标是让用户本人通过站点提供的正常交互完成人机验证，不是让自动化绕过挑战。

## 触发与优先级

1. 保存当前页面 URL、非敏感阶段名称和挑战类型；不要保存挑战 Token、完整 HTML、Cookie、请求头或浏览器配置文件。
2. 立即停止自动点击、表单提交、挑战重试和签到请求，避免重复触发风控。
3. 显式调用 `$camofox-browser` 并读取其当前说明。若该 Skill 不可用，直接进入 `UNSUPPORTED_SECURITY_CHALLENGE`，不要临时编写规避脚本。
4. 本文的授权与禁止边界优先于 CamoFox 中面向反检测或规避检测的用法。不得启用代理轮换、指纹轮换、地区伪装、自动验证码求解、第三方打码、挑战 Token 提取或挑战结果重放。

## 有界的 CamoFox 尝试

1. 为当前授权账号使用稳定、非敏感的 `userId` 与同一会话；账号之间不得共用 profile、Cookie 或标签页。
2. 只进行一次正常页面导航或刷新，用于排除普通浏览器兼容性、页面未加载完成或会话状态丢失。不得针对挑战控件编写点击、拖动、识别或求解逻辑。
3. 若页面在正常导航下不再显示挑战，可重新获取页面快照并继续正常取证。
4. 若挑战仍存在、需要交互，或不能明确确认已经消失，立即进入 noVNC 人工接管，不继续自动尝试。

## 打开 noVNC 并请求人工通过

按 `$camofox-browser` 的 display/VNC 流程执行：

1. 对当前 `userId` 调用 `POST /sessions/:userId/toggle-display`，请求体使用 `{"headless":"virtual"}`。该操作会重启浏览器上下文，使已有 tab ID 和元素引用失效。
2. 从响应中读取 `vncUrl`。不要在文档、日志或消息中展开它的查询参数；把完整地址视为临时敏感会话地址，不写入仓库、日志、通知或截图。
3. 切换显示模式后，使用相同的 `userId`、`sessionKey` 和原页面 URL 创建新标签页；不要继续使用切换前的 tab ID 或元素引用。
4. 使用可用的用户可见浏览器控制能力打开返回的 `vncUrl`，明确告知用户“请仅在 noVNC 页面中手动完成站点的人机验证；完成后回到对话确认”。不要只在后台等待，也不要让自动化接管挑战控件。
5. noVNC 会话存在超时。向用户说明剩余时间；若超时或 URL 无法打开，可在仍获授权的前提下重新创建一次可视会话，不得无限重试。
6. 等待用户明确确认完成。等待期间不得读取、复制或记录用户在 noVNC 中输入的密码、验证码、短信码或其他秘密。

## 人工完成后的恢复与判定

1. 收到用户确认后，在同一 `userId` 的 virtual display 会话中重新枚举标签页并获取新快照，验证挑战页面已经离开。不要从旧引用继续操作。
2. 只恢复签到接口识别、状态查询和脱敏取证。若用户尚未确认，或挑战仍存在，不发送签到请求。
3. 若之后切回 headless，显示切换会再次使标签页失效；切换后重新创建标签页并重新获取引用。
4. 人工通过只证明当前交互会话可继续，不证明 GitHub Actions、青龙或本地定时任务能够无人值守运行。必须单独验证目标部署环境不会再次要求挑战。
5. 出现以下任一情况时返回 `UNSUPPORTED_SECURITY_CHALLENGE`：CamoFox 或 noVNC 不可用；用户取消或未完成；挑战循环出现；需要提取或重放挑战产物；需要隐藏自动化或规避检测；定时任务仍依赖人工处理。

## 禁止写入生成项目

不要把 CamoFox/noVNC 人工接管、浏览器 profile、挑战 Cookie、验证码、短信码、挑战 Token、VNC Token 或 `vncUrl` 写入生成的签到项目、工作流、青龙脚本、测试 fixture、文档示例或通知。生成项目只能实现已经证实不依赖挑战绕过的正常签到请求。
